# 🧭 Technology Architecture Philosophy

<div align="center">

### CHOOSE TECHNOLOGY BASED ON THE SYSTEM.

### NOT THE OTHER WAY AROUND.

</div>

<br>

When thinking about a new system, I consider:

| Question                     | Why it matters                  |
| ---------------------------- | ------------------------------- |
| What problem are we solving? | Prevents unnecessary complexity |
| Who uses the system?         | Defines product requirements    |
| What data exists?            | Determines architecture         |
| What needs to scale?         | Influences infrastructure       |
| What can fail?               | Drives resilience               |
| What needs protection?       | Drives security                 |
| What can be automated?       | Drives DevOps                   |
| Where can AI help?           | Creates intelligent workflows   |
| How will it be monitored?    | Enables production visibility   |

# 🧰 Engineering Principles

### 01 — Problem First

Technology should serve a problem.

### 02 — Architecture Matters

Good engineering starts before implementation.

### 03 — Security Early

Security should not be postponed until deployment.

### 04 — Automate Repetition

Automation creates consistency and saves engineering time.

### 05 — Observe Production

A deployed system needs visibility.

### 06 — Build for Change

Requirements evolve. Architecture should allow evolution.

### 07 — Learn by Building

Projects are one of the best ways to understand technology deeply.

### 08 — Ship

A working system teaches more than an unfinished idea.
